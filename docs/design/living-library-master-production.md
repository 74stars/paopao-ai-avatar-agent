# 活书房原稿复原与交互场景生产规范

> 状态：P1/P2/P3 日景和 P4 夜景完整场景帧包已完成当轮人工确认。P5 完整场景帧运行方案已于 2026-08-15 通过工程验收；历史 v4/v4.1 源码、设计副本和发布副本已按显式清单删除。书组素材仍只批准组级抽象表现，不再校准单本书籍一致性。
> 目标来源：2026-08-12 用户确认
> 本文只约束本轮活书房美术生产，不把历史实现、工程测试或自动指标作为美术依据。

## 1. 目标

以确认的写实活书房原稿为画面和空间基准，修复原稿背景，并将画面中的真实物件开发为可交互界面。

最终画面必须保持原稿的：

- 构图、视点和空间比例；
- 木作、金属、玻璃、纸张等真实材质；
- 连续且可信的环境光、接触阴影和反射；
- 打字机、信件托盘、书架、台灯和窗景之间的原始空间关系。

目标不是复刻当前程序画面，也不是制作新的剪贴画、卡片界面或 3D 场景。

## 3. 禁止项

- 不使用 CSS 绘制书架、纸张、按钮、图标、光晕或其他场景物件。
- 不使用始终不变化的静态背景加透明热点冒充物件反馈；完整场景方案必须提供与真实物件对应的状态帧。
- 不将不同风格、不同视角或不同光照来源的孤立素材拼进画面。
- 不用发光描边、整体缩放、悬浮卡片或矩形贴片表达场景交互。
- 不在书房中放置第二个泡泡角色。
- 不以截图测试、像素指标或工程 Gate 宣布美术通过。
- 不继续修饰 `v4/v4.1` 以代替原稿复原。

## 4. 场景生产结构

新资源位于 `desktop-app/design/assets/library-world-master-v1/`，在完成美术复核前不覆盖当前运行资源。

### 4.1 母版坐标

- 设计坐标：1800 x 1126。
- 所有物件 bounds、pivot、入口文字坐标和命中区域均使用母版像素坐标。
- 运行窗口使用 cover 策略；只能等比裁切边缘，不得拉伸或重排物件。

### 4.2 图层

1. `architecture-plate-day`：移除所有需要交互的物件后，补全书柜、墙面、桌面和被遮挡区域。
2. `ambient-day`：不随交互变化的连续环境光与全局色调。
3. `object-*`：来自同一原稿的真实物件静止态。
4. `shadow-*`：物件接触阴影；只有确实需要独立运动时才拆分。
5. `effect-*`：玻璃高光、灯焰和局部光池等半透明效果。
6. `runtime-label-*`：仅包含木横板上的六个分类入口文字，不写入物件纹理。

### 4.3 可逆合成约束

在交互实现前，必须满足：

`architecture plate + all idle objects + shadows/effects ~= day master`

该检查用于发现坐标、边缘、色调和遮挡关系漂移。数值差异只提供工程诊断，实际取舍由并排画面评审决定。

## 5. 产品语义边界

本文不再定义产品入口、文字、状态机或业务层呈现。当前单一设计来源为 [活书房全局交互修正设计](living-library-global-design.md)。

美术生产只接受该全局设计列出的场景对象：六组分类书籍、静止打字机、信件托盘和台灯。搜索与设置属于窗口工具，不生产或添加虚构的桌面物件。

## 6. 生产阶段

### P1 日景底板

- 从日景母版移除打字机、信件托盘、台灯和计划拆分的交互物件。
- 补全其后的木作、桌面、书柜暗部和反射。
- 不改变相机、书架结构、窗景、颜色关系和裁切。

### P2 日景静止态分层

- 使用原稿完整画面和对应物件局部作为模型参考，逐件重绘打字机、信件、台灯和分类书组。
- 不把原稿背景矩形、邻近木作或桌面反光直接抠入物件层；主体、接触阴影与复杂光学效果按运动需要分别生产。
- 每个物件先检查模型原始输出、透明边缘和回填完整场景，确认视点、比例、材质、光照与原稿一致后再制作下一件。
- 玻璃、火焰和软阴影不得假设普通色键可以无损处理，必须采用适合该光学关系的模型状态帧或独立覆盖层。
- 完成静止态重合成并输出并排画面。

- 通过依据是室内木作、书墙、桌面和实体物件均获得明确日间可见度，同时保留原稿的自然光方向、材质连续性、克制曝光和空间关系。

### P3 交互状态

- 每次只生产一个物件的一种状态。
- 变体必须复用静止态坐标、透视和照明条件。
- 动画优先使用少量状态帧和小幅位移，不进行程序化材质替代。
- 书组抽出状态可以作为整体交互表达使用；若模型无法保持每本书的身份一致性，不得将单本书脊拆成跨状态复用的独立资产，也不得把单本纹理、宽高和磨损细节当作稳定产品语义。
- 书组状态后续不再尝试校准单本书籍一致性。所有书组只按整体空间运动验收：前移是否可辨认、前后层次是否成立、两侧遮挡是否自然、后部暗槽和搁板接触是否可信。

### P4 夜景

- 从已经确认的日景底板与物件派生。
- 保持所有几何和遮挡关系不变。
- 台灯切换必须同时影响火焰、玻璃、桌面反射和邻近木作。

### P5 运行时替换

- manifest 继续描述完整场景帧、坐标、命中区域和书架文字位置。
- 运行时继续负责完整状态帧切换、透明命中交互和书架入口文字，不重新生产场景图层。
- 书组和信件继续使用已经确认的完整状态帧；六个分类沿用当前组级抽象映射。
- 打字机只使用静止完整帧，不生产或接入抬纸状态。
- 新状态帧必须在加载并解码完成后替换当前可见帧，不能在加载空档显示黑底。
- 当前增量交互修正见 [活书房全局交互修正设计](living-library-global-design.md)。

### P5 本轮美术指导

- 完整母版帧铺满窗口，保持原稿相机、裁切、窗景、木作结构、桌面边缘和物件空间关系。
- 不用 CSS 绘制场景物件、光影、悬浮卡片或第二个泡泡。
- 交互反馈继续由真实物件对应的审核完整帧体现：托盘信件抬起、书组整体抽出、台灯日夜切换。
- 可见常驻入口文字只位于书架木横板；打字机、信件、台灯、搜索和设置不放常驻文字。
- 程序截图和自动检查只记录工程事实，不能替代人工美术判断；本轮运行截图必须直接查看并输出新的指导意见。
- 本阶段禁止使用录屏、桌面视频采集或占用桌面的动态检测；工程验证只使用静态素材直读、资源请求、DOM/交互状态和构建测试。

## 7. 生图与编辑方法

- 用例类型：`precise-object-edit`。
- 图像 1 始终标记为 edit target，不是松散风格参考。
- 使用 GPT Image 编辑现有母版，优先局部编辑而非重新生成整个场景。
- 每轮 prompt 都重复不变量：只修改指定区域，保持构图、视点、木作结构、窗景、其他物件和光照关系不变。
- 先产出版本化 PNG，不覆盖母版；人工选定后才转为运行格式。
- 透明图层优先使用原稿像素与本地蒙版。玻璃、火焰、软阴影等复杂透明对象不使用色键抠图。

## 8. 每轮美术指导

每轮必须输出未经标注的原稿、候选和运行截图，并记录：

1. 当前画面问题；
2. 与原稿的判断依据；
3. 应保留的部分；
4. 下一轮只解决的一组具体问题；
5. 工程事实与美术判断的明确分离。

记录不设 `PASS/FAIL`、风格分数或自动关闭条件。是否继续进入下一阶段由用户查看实际画面后决定。
