# 活书房截图采样与工程检查

本 runbook 只生成可信的运行截图和工程事实，不执行美术审核，也不定义目标风格。

## 1. 采样信息

每次采样记录：

- commit SHA 和工作树状态；
- 操作系统、窗口尺寸、DPR 和主题；
- 数据状态与使用的合成 fixture 标识；
- 应用启动方式、截图时间和输出路径；
- renderer error、资源加载失败和缺失状态。

截图不得带调试遮罩、测量网格或测试报告 UI。需要测量时另存证据图，不能覆盖原始候选截图。

## 2. 状态矩阵

至少采集空、加载、错误、真实列表、记录详情和设置遮罩状态，并覆盖 1366x768、1440x900、1920x1080。交互动效另记录起始帧、反馈帧和稳定帧。

## 3. 工程检查

可以自动判断：

- Canvas 和截图是否非空；
- 图片、字体和 manifest 是否成功加载；
- 视口是否出现未覆盖区域、裁切、溢出或异常重叠；
- 交互对象是否可达并触发真实业务动作；
- 透明通道、DPR 和 renderer error 是否符合运行要求；
- 截图是否来自指定状态而非静态 fixture 页面。

这些结果必须标记为工程检查。即使全部通过，也只能说明候选可被可靠查看和操作。

## 4. 美术评审交接

把原始截图、必要的状态说明和本轮用户参考交给人工评审。不要附加自动美术评分或建议评审“确认通过”。

每轮评审返回：

- 整体判断和主要矛盾；
- 按影响排序的问题；
- 对应截图位置和判断依据；
- 应保留的部分；
- 下一轮具体美术指导；
- 需要新候选继续验证的事项。

评审记录没有 PASS/FAIL 字段。工程问题回到对应代码 owner；美术问题进入下一轮候选设计。
